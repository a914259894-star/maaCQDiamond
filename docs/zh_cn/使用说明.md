# 使用说明

克鲁赛德战记（Crusaders Quest）「试炼」循环工具，基于 MaaFramework 实现。

## 一、运行前准备

| 项目 | 要求 |
| --- | --- |
| 模拟器 | MuMu 12，游戏 `com.nhnent.SKQUEST`，**横屏** |
| 分辨率 | 任意，但截图会被缩放到短边 **720（1280×720）**，模板与坐标都按此制作 |
| 起始界面 | **主城**（进入游戏后的城镇场景） |
| 网络 | 建议开加速器。Gamebase 偶发 `errorCode: 4201` 网络错误弹窗属正常现象，工具会自动点掉 |
| 运行环境 | **发布包无需额外配置**：已内置 Python 与依赖，解压后直接运行 `MFAAvalonia.exe` |

启动方式：解压发布包 → 双击 `MFAAvalonia.exe` → 设备列表选择 MuMu 模拟器 → 任务选「试炼循环」。

> **首次使用务必先检查「截图方式」**：MFAAvalonia 给 MuMu 的设备预设只勾了 EmulatorExtras，
> 这种方式在 MuMu 上会偶发取不到画面，表现就是「任务在跑但一个都不点」。请把它改成
> **默认（多种方式自动测速）**。详见文末常见问题第一条。

> 开发调试时才需要项目内 `.venv`：此时 `assets/interface.json` 的 `agent.child_exec`
> 指向 `../.venv/Scripts/python.exe`；打包时 `tools/install.py` 会自动改写为随包的 `./python/python.exe`。

## 二、任务与选项

- **试炼循环**：完整循环，次数用尽后自动重置账号并继续。
- **单次试炼（次数用尽即停，不删号）**：只打当前剩余次数，**不会**触发删除账号，适合先验证。

`循环次数` 选项等价于限制「回到主城」的次数（即循环轮数）。

## 三、流程节点

```
主城 ─开始→ 模式选择 ─冒险→ 冒险页 ─试炼→ 试炼页
      │
      ├─ 还剩N次 (N>0) → 选1组 → 开始 → 队伍设置 ─队伍→ 选择队伍 ─选择→
      │                 队伍设置 ─开始→ 队伍锁定[确认] → 战斗
      │
      └─ 还剩0次 → 逐级退回主城 → 菜单 → 账号 → 账号管理 → 删除账号
                     → 勾选校验 → 确定 → 确认 → 账号登录 → Sign in with Google
                     → 选最下方谷歌账号 → 账号删除引导[撤销] → 标题页 TAP
                     → 【公告弹窗：点右上 ×】→ 主城（新一轮）

战斗结束 → 结算：
   · 胜利且 N>0 → 下一个区域（蓝色）→ 下一场
   · 失败且 N>0 → 重新挑战（蓝色）→ 下一场
   · N=0        → 返回城镇（两个按钮都灰）→ 账号重置
```

### 弹窗兜底

| 弹窗 | 识别方式 | 处理 |
| --- | --- | --- |
| 登录后的游戏公告（左上「公告」标题） | 右上角「今日不再显示 + ×」区域模板匹配（`NoticeClose.png`，实测 1.0 vs 其它界面 ≤0.64） | 点右上 × 关闭 |
| 每日签到 / 快乐CQ每一天 | 左侧「签到奖励」标签模板匹配（`CheckInPanel.png`，实测 1.0 / 0.92 vs 其它界面 ≤0.58） | 点右上 × 关闭 |
| `errorCode: 4201` 等网络错误 | OCR 命中 `errorCode` / `请稍后再试` / `网络不稳定` 等 | 点「确认」关闭 |
| 「无法进入！一定时间内无法进入」 | OCR 命中 `无法进入` / `一定时间内` | 点「确定」关闭 |

处理后自动回到原流程继续，因此不管弹窗出现在哪一轮都能被吃掉。

## 四、战斗逻辑说明

战斗由 `agent/battle.py` 的自定义动作 `battle_loop` 接管，独立于流水线循环：

1. **方块条**：后台线程每 80ms 点击一次「最右侧方块」位置（1280 空间 `1132, 653`），实测约 9 次/秒。
2. **领主**：主循环截屏后统计领主区域红条占比，≥0.12 即认为出现 `TOUCH`，点击 `830, 562`。
   （实测：就绪 0.17~0.21，未就绪 0.00~0.05）
3. **女神**：统计女神区域青蓝色占比，≥0.12 即认为有能量格填满，点击 `1140, 562`。
   （实测：就绪 0.18~0.55，未就绪 0.00~0.04）
4. **结束判定**：结算界面「返回城镇」模板命中即结束；随后清理「开启练习模式」等弹窗。

截图与点击共用同一个控制器，是串行执行的，所以识别频率直接决定了连点速度。
现在主循环按 `reco_interval`（默认 0.5 秒）节流，两次识别之间的空档全部让给连点线程，
并且用 `min_click_window`（默认 0.25 秒）兜底 —— 截图再慢也会留出固定的连点窗口。
adb 截图约 260ms 时可达到 **8~10 次/秒**（旧版固定 120ms 间隔只有 2~3 次/秒）。

若你的模拟器开了 EmulatorExtras 截图（约 23ms/张），连点还能更快；但它在 MuMu 上
偶发取不到画面，建议按「常见问题」里的说明配置截图方式。

所有坐标/阈值都可通过节点的 `custom_action_param` 覆盖，例如：

```jsonc
"Battle_Loop": {
    "custom_action_param": {
        "bar_point": [1132, 653],
        "red_threshold": 0.15
    }
}
```

## 五、安全设计

- **勾选校验**：删除账号页若「有7天的删除冷静期」未勾选，会立即停止任务并打印提示，等你人工判断。
- **连续失败保护**：连续 3 次「重置后次数仍为 0」会停止任务，避免无限删号。
- **识别不到次数**：直接停止，不做任何破坏性操作。
- 想完全避免删号：请用任务「单次试炼（次数用尽即停，不删号）」。

## 六、常见问题

**Q：任务在跑但一个都不点（最关键的一条）**
先确认设备设置里的**截图方式**。MFAAvalonia 给 MuMu 的默认预设是只勾 **EmulatorExtras**，
这种方式在 MuMu 上会偶发取不到画面（日志里是 `实时画面为空` / `get_display_id Failed`），
一旦取不到图，所有识别都会失败，表现就是「任务看着在跑，但完全不动」。

正确做法：把截图方式改成**默认（多种方式自动测速）**，不要只留 EmulatorExtras。
如果是直接改配置文件，把 `config/instances/default.json` 里的
`"ScreencapMethods": 64`（只有 EmulatorExtras）改成 `18446744073709551559`
（这是 MaaFramework 的 `AdbScreencapMethods.Default`：除 RawByNetcat / MinicapDirect /
MinicapStream 三种外全部参与自动测速）。**改之前先关掉 MFAAvalonia**，
否则退出时会被界面覆盖回去。

现在 agent 的截图函数会在拿到空图时直接报错并提示这条原因，不会再静默失败。

> 另注：换解压目录（升级新版本）会重新生成 `config/`，需要再改一次。

**Q：卡在某个界面不动**
看 agent 日志里最后一条 `[node]`。多半是该页面的模板分数不够，重新截一张当前页的 1280×720 图，
裁剪对应按钮覆盖 `assets/resource/image/` 下的同名文件即可。

**Q：点了按钮但页面没反应**
游戏在转场/加载时会吞掉点击。关键跳转节点（主城开始、模式选择、冒险页试炼）都配了重试节点，
会自己补点；如果某个新界面也出现这种情况，照着 `Town_Start_Retry` 的写法加一个 `xxx_Retry` 即可。

**Q：试炼页弹出「惊喜问答」，任务停了**
这是游戏的活动答题：四个角色依次跑过，要回答右侧角色排第几。
**答错会触发「无法进入！一定时间内无法进入」的冷却**（实测从 43 秒涨到 8 分钟），
自动乱猜只会越来越糟，所以工具检测到就直接停下并提示，请手动答完再重新启动任务。

**Q：点到冒险页里面的「剧情」去了**
原因是重试节点点击前会等「画面静止」，而这段时间页面刚好跳转，点击就落到了新页面同坐标上
（冒险页最左就是剧情卡）。现在重试节点已去掉这个等待，改为识别到就立刻补点，
同时把各页面的点击间隔（`post_delay` / `rate_limit`）整体放慢。

**Q：领主/女神一直不点**
该关卡可能限制了「禁止使用女神 / 禁止使用领主」（试炼右侧的负面效果列表），此时不会出现 TOUCH，属于正常。

**Q：adb 连不上**
MuMu 的 adb 端口会变（16384 / 16416 / 7555）。用 `D:\MuMuPlayer\nx_main\adb.exe devices` 确认当前端口。
