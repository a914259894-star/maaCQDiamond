# 使用说明

克鲁赛德战记（Crusaders Quest）「试炼」循环工具，基于 MaaFramework 实现。

> **v2 完全重写**：整条流程只用 Pipeline JSON 描述（识别标志 → 点击），
> 不再包含任何 Python Agent 代码，也没有自定义动作。要用到的所有设置都保持默认。

## 一、运行前准备

| 项目 | 要求 |
| --- | --- |
| 模拟器 | MuMu 12，游戏 `com.nhnent.SKQUEST`，**横屏** |
| 分辨率 | 任意。截图统一缩放到短边 **720（1280×720）**，标志图与点击坐标都按此制作 |
| 起始界面 | **主城**（进入游戏后的城镇场景） |
| 网络 | 建议开加速器。Gamebase 偶发 `errorCode: 4201` 网络错误弹窗属正常，工具会自动点掉 |
| 运行环境 | **发布包无需额外配置**：已内置 MaaFramework，解压后直接运行 `MFAAvalonia.exe` |

启动方式：解压发布包 → 双击 `MFAAvalonia.exe` → 设备列表选择 MuMu 模拟器 → 任务选「试炼循环」。

> 截图方式、点击方式等全部保持 MFAAvalonia 的默认值即可，本工具不做任何改动，
> 也不需要在「设备设置」里额外勾选什么。

## 二、任务

| 任务 | 入口节点 | 说明 |
| --- | --- | --- |
| **试炼循环** | `Main` | 完整循环。次数用尽后自动删号并重新登录，恢复次数后继续 |
| **重置次数（删号）** | `Reset_Start` | 只跑「回主城 → 菜单 → 帐号 → 删除帐号 → 重新登录」这一段，用来单独验证删号链路 |

## 三、整体思路：识别标志 → 点该点的东西

主流程就是一个分发节点 `Main`：

```
Main（DirectHit，不做动作）
  → 每轮重新截图，按优先级依次比对下面所有页面的「标志图」
  → 命中哪个页面，就执行那一页的点击动作
  → 动作完回到 Main，重新截图
  → 谁都认不出（加载、转场）→ Wait 等 0.6 秒再看
```

每个页面只用一张「标志图」定位，标志图都是从真实截图里裁的、并且验证过在别的页面分数明显更低：

| 页面 | 标志图 | 判定 / 动作 |
| --- | --- | --- |
| 标题画面 | `TitleBottom.png` | 点屏幕中央进入游戏 |
| 主城 | `m_town.png`（底部图标栏左段） | 点右下「开始」→ 模式选择 |
| 模式选择 | `m_mode.png`（冒险传送门石雕） | 点「冒险」 |
| 冒险关卡列表 | `m_adventure.png`（左上「冒险」标题） | 点「试炼」卡片 |
| 试炼页 | `m_trial.png`（左上「综合分数」） | 见下：按「开始」按钮颜色分流 |
| 队伍编成 | `m_team_edit.png`（标题） | 按「开始」按钮颜色分流 |
| 选择队伍 | `m_team_select.png`（标题） | 点右下「选择」 |
| 战斗中 | `m_battle.png`（右上角图标） | 进入连点循环 |
| 结算 | `m_result.png`（结算标题条） | 按按钮颜色分流 |

分流都用 **ColorMatch**（`method: 4` 是 RGB 顺序）判按钮是蓝还是灰：

- 试炼页「开始」**蓝** → 点它开打；**灰** → 先看左侧「1组」是否选中（未选中底色
  RGB(74,77,123)，选中是 RGB(107,105,181)）：没选中就点「1组」再回来，
  选中了还灰就 OCR 确认按钮上方红字是「还剩0次」才进删号链路
  （红字「还剩N次」次数>0 时也在，必须读出 0 才算数）。
- 队伍编成「开始」**蓝** → 点它；**灰** → 队伍是空的，点左侧绿色「队伍」按钮
  打开预设列表 → 点「选择」带回队伍 → 开始变蓝后正常开打。
- 结算页「下一个区域」「重新挑战」**蓝** → 点；两个都灰 → 点「回城」进删号链路。

## 四、战斗逻辑

确认进入战斗（`m_battle.png` 命中）后：

```
Battle_Tap1 → Battle_Tap2 → … → Battle_Tap8
                                   ├─ Battle_Lord   （领主进度条出现 TOUCH → 点领主）
                                   ├─ Battle_God    （女神能量槽出现 TOUCH → 点女神）
                                   ├─ Page_Result   （进入结算）
                                   └─ Battle_Tap1   （继续连点）
```

- **方块条**：8 个 `DirectHit` 节点串联，每个都盲点最右侧方块位置 `1156, 634`。
  `DirectHit` 不需要截图，所以这 8 次点击几乎没有间隔，一轮约 640ms；
  加上最后识别一次 `TOUCH` 的截图耗时（约 320ms），实际约 **8 次/秒**。
- **领主 / 女神**：用同一个 `TOUCH` 横幅模板 `m_touch.png`，分别在两个 roi 里找。
  领主 roi `[755,535,200,55]` → 点 `830,562`；女神 roi `[1040,535,215,55]` → 点 `1140,562`。
  模板分数实测在对应位置 **1.000**。
- 该关卡如果写了「禁止使用领主 / 禁止使用女神」，进度条上不会出现 TOUCH，
  此时不点属于正常现象。

## 五、删号恢复次数链路

试炼一轮只有 4 次。用完后的处理：

```
试炼页「开始」变灰（或结算页两个按钮都灰）
  → 一路退回主城：试炼页 ×  → 冒险页 ×  → 模式选择「城镇」
  → 主城右上角菜单图标 → 菜单弹窗「帐号」图标
  → 帐号弹窗「帐号管理」 → 账号管理弹窗「删除账号」
  → 删除页：检查「有 7 天的删除冷静期」是否已勾选（绿色）
      · 已勾选（绿）→ 点「确定」
      · 未勾选（灰）→ 点一下勾选条，再重新判断
  → 第二层确认框「确认删除账户 / 真的要退出吗？」→ 点「确认」
  → 游戏退出重启（LOAD）→ 登录页 → 「Sign in with Google」
  → 谷歌「选择账号」列表 → 点下面那个邮箱（第二行，工作账号）
  → 「账号删除引导 / 该账号处于删除流程中。是否撤销删除？」→ 点「撤销」
  → 账号恢复、次数重置为 4 → 加载 → 标题页 → 主城 → 回主循环
```

以上每一步都按真机录屏核对过（205s 菜单 / 206s 帐号 / 210s 帐号管理 / 211s 删除页 /
216s 第二层确认 / 219s 登录页 / 223s 选号 / 225s 撤销弹窗）。

**为什么一定要勾「7 天的删除冷静期」**：勾了只是提交删除申请，7 天内登录可以撤销；
不勾就是立即永久删除、无法恢复。所以工具会先确认这一项是勾上的，勾错了绝不会点「确定」。

**选号为什么点第二个**：谷歌账号列表里第一个是另一个号，第二行才是本工具使用的账号。
工具用 OCR 取「含 @ 的最后一行」，所以「添加其他账号」这种没有 @ 的条目不会被误点。

## 六、安全设计

- **冷静期校验**：删除确认页必须先检测到勾选条发光（绿色 ColorMatch ≥ 4000 像素）才点「确定」，
  否则只会去点勾选条，不会提交删除。
- **不会瞎点**：每个节点都是「识别到标志才动作」。标志不在就什么都不做，
  由 `Wait` 兜底继续等，不会因为一次误判就去点别的按钮。
- **弹窗兜底**：「惊喜问答」识别到就停任务（见常见问题）；签到 / 公告 / 确认框统一处理。
- **不想删号**：不要运行「试炼循环」，或在它进入删号阶段前手动停止即可；
  也可以只跑「单次」——把 `Main` 里 `Trial_NoCount` 的 `next` 改成 `[]` 即可关闭删号。

## 七、常见问题

**Q：任务在跑但完全不动，日志里出现「实时画面已连接但无法获取画面」**

模拟器的安卓虚拟机没有在运行（或被切到了后台 / 掉线）。判断标志：MFAAvalonia
顶部的**截图耗时**，正常应为 300ms 左右（Adb 截图）或几 ms 的真·EmulatorExtras；
如果显示 **0~6ms** 还配着黄色警告，说明截图拿到的是空帧，所有识别必然全空。
处理：确认 MuMu 里安卓系统已经开机、游戏在前台，然后在 MFAAvalonia 里**刷新设备**、
重新选择正确端口（MuMu 实例重启后端口可能变化，例如 16416 → 16417 → 16416），
确认黄色警告消失后再启动任务。

**Q：任务在跑但一个都不点**

八成是画面没取到。先确认模拟器没被最小化、游戏在前台；再看日志有没有取图失败的报错。
本工具不改任何截图设置，保持 MFAAvalonia 的默认即可。

**Q：卡在某个界面不动**

看日志里最后一个进入的节点名。多半是该页面的标志图分数不够，
重新截一张当前页的 1280×720 图，按上表的位置裁一张覆盖 `assets/resource/image/` 下的同名文件。

开发期可以用 `.workbuddy/tools/mkmarks.py` 重新裁所有标志，它会打印
`本页=1.000 差=+0.5xx | 前三名`，要求「本页 ≥0.95 且和别的页面差 ≥0.15」。

**Q：点了按钮但页面没反应**

游戏在转场/加载时会吞掉点击。所以每个点击节点都把「目标页面」放在 `next` 的第一位，
识别不到时就在同一页再点一次（`next` 里带上自己），点中后标志消失自然就不再重试。

**Q：试炼页弹出「惊喜问答」，任务停了**

这是游戏活动答题：四个角色依次跑过，要回答右侧角色排第几。
**答错会触发「无法进入！一定时间内无法进入」的冷却**（实测从 43 秒涨到 8 分钟），
自动乱猜只会越来越糟，所以工具检测到（`SurpriseQuiz.png`）就直接停任务，请手动答完再重新启动。

**Q：领主 / 女神一直不点**

该关卡限制「禁止使用女神 / 禁止使用领主」时不会出现 TOUCH，属于正常。

**Q：adb 连不上**

MuMu 的 adb 端口会变（16384 / 16416 / 7555）。用 `D:\MuMuPlayer\nx_main\adb.exe devices`
确认当前端口，在 MFAAvalonia 的设备设置里填对即可。

## 八、给开发者

```bash
.venv\Scripts\python.exe .workbuddy\tools\lint.py         # 静态检查：JSON、节点引用、模板文件
.venv\Scripts\python.exe .workbuddy\tools\simulate.py     # 离线跑分发：每张截图会被认成哪个页面
.venv\Scripts\python.exe .workbuddy\tools\run_pipeline.py # 真机直跑流水线，实时打印进入的节点
.venv\Scripts\python.exe .workbuddy\tools\nav.py tap 640 360   # 按 1280 空间坐标点真机
```

流水线按页面拆成三个文件，全部会被递归加载：

- `00_main.json`：`Main` 分发 + 正常流程各页面
- `01_battle.json`：战斗连点 / 领主女神 / 结算分流
- `02_reset.json`：删号恢复次数链路
- `99_common.json`：弹窗兜底（问答 / 确认框 / 签到 / 公告）
